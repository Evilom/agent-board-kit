# 设备与工程协作（0.4）

在任意已授权设备上找到工程，读取已有资料，调用工程所在设备的文件、命令或服务能力，再把真实结果带回当前会话。另一台电脑上的聊天窗口不需要打开。设备后台只运行连接与工具，不启动模型。

## 日常使用

1. `board_resources` 搜索工程名称或别名，例如 `MyWeb`、`博客`。
2. 用 `board_remote` 的 `context` 读取工程规则、流程、可用命令和服务名称。
3. 按当前用户授权调用文件或服务操作。用 `board_operation` 查询同一操作的结果。
4. `board_shared_knowledge` 查询已有授权知识和服务端本机已共享的工程资料；结果附来源和 SHA256。其他设备的资料可用对应资源的 `search` 操作查询。

`queued` 是等待设备，`running` 是执行中，`succeeded` 才表示设备报告操作成功。`uncertain` 表示可能已经发生效果，需要核实原操作，不能换一个编号重试。执行成功也不等于一篇文章、一个产品或整个用户目标已经验收。

旧版任务、消息、认领和交接仍兼容。设备工具解决直接操作工程的问题；任务板继续记录目标和验收依据。不要把设备操作完成代替旧任务的处理确认。

## 一次接入设备工具

程序更新走既有 Git 主分支：Windows 使用 `scripts/update.ps1`，Mac 使用 `scripts/update.sh`。脚本只快进拉取，备份原配置并运行相关测试；源码存在本地改动时停止。更新后重启已有设备服务并重新加载 MCP。

保留本机已有配置和配对令牌。主电脑继续使用 `.runtime/config.json`，副电脑使用原 `.runtime/client.json`。更新程序后，备份升级配置并重启原服务：

```sh
python3 agent_board.py network --config .runtime/config.json upgrade
python3 agent_board.py network --config .runtime/config.json service
```

登录后自动运行设备连接：

```sh
# 先停止旧的 service；该命令只启动设备服务，不启动模型。
python3 agent_board.py network --config .runtime/config.json service-install --activate
```

Mac 使用用户 LaunchAgent，Windows 使用当前用户的计划任务，Linux 使用 systemd 用户服务。Windows 将 `python3` 换成本机 Python，将配置换成 `.runtime/client.json`。安装器生成的服务定义不包含令牌或 API key。服务不能使已关机的设备保持在线。

### 持久 MCP 连接

设备级入口不依赖 project/name/session，也不注册或冒用聊天 Agent。Codex 只需登记一次：

```sh
codex mcp add agent_ecosystem -- /绝对路径/python3 /绝对路径/agent_board.py network --config /绝对路径/本机配置.json ecosystem-mcp
```

其他支持 MCP 的应用使用以下命令返回的配置：

```sh
python3 agent_board.py network --config .runtime/config.json ecosystem-connection
```

该入口提供 5 个工具：`board_resources`、`board_remote`、`board_operation`、`board_cancel_operation`、`board_shared_knowledge`。原会话型 MCP 则提供完整的 26 个工具。已有聊天窗口可能需要重新加载 MCP 才能看到新工具；保存连接不会为一个已经启动的会话伪造工具绑定。

## 一次登记工程与访问范围

所有配置仍在设备已有的统一配置文件中。以下为 `resources.myweb` 的示例（参数需使用设备真实路径）：

```json
{
  "root": "/Users/om/projects/MyWeb",
  "project": "myweb",
  "name": "MyWeb",
  "aliases": ["博客", "个人网站"],
  "description": "博客来自 Notion；先读取上下文，再沿用现有内容与发布流程。",
  "access": {"windows-main": ["read", "write", "run"]},
  "read_prefixes": ["AGENTS.md", "README.md", "package.json", "docs", "app", "lib", "public"],
  "write_prefixes": ["docs/content-updates", "public/agent-board"],
  "context_files": ["AGENTS.md", "README.md", "package.json"],
  "knowledge_prefixes": ["AGENTS.md", "README.md", "docs/content-updates"],
  "commands": {
    "build": {"description": "构建网站", "argv": ["/绝对路径/pnpm", "build"], "timeout": 900}
  }
}
```

可以先将这份工程描述写入临时 JSON，再通过 `resource-add --key myweb --spec 文件.json` 登记；命令验证并备份旧配置，保留原凭据和其他条目。配置变更在设备下一次心跳生效。服务端本地共享知识的配置变化需要重新加载服务。

工程必须由所属设备发布，不能把 Windows 的根目录当成 Mac 目录执行。远端设备只看到自己被授权的资源；`read`、`write`、`run` 分别控制读取、更新指定文件、调用配置好的命令/服务。设备拥有者的只读凭据不会因此获得执行权限。

## 文件与命令操作

`board_remote` 的公共参数为 `resource_id`、`request_id`、`operation` 和 `arguments`；可关联既有 `work_id`。同一次请求的网络重试必须沿用 request_id，改变参数会被拒绝。

| operation | arguments | 行为 |
|---|---|---|
| `context` | `{}` | 原文、来源、SHA256、命令和凭据引用名称 |
| `search` | `query` | 查询该工程配置的知识原文 |
| `list` | `path`，可选 `after` | 分页查看授权目录 |
| `read` | `path` | 读取不超过 256 KiB 的 UTF-8 文件 |
| `stat` | `path` | 实读完整文件的大小与 SHA256 |
| `write` | `path`, `content`, `expected_sha256` | 原子更新 UTF-8 文件；新文件使用 `absent` |
| `run` | `command` | 运行设备配置中的固定命令；返回退出码和有界输出 |
| `request` | `service`，可选 `parameters`, `body` | 调用已配置的固定服务接口，在本机注入凭据 |

路径使用相对路径和 `/`。禁止越出共享根目录、绕过读写前缀、读取 `.env`、密钥、运行状态目录等。符号链接也需要通过解析后的路径检查。写入时原文件的 SHA256 必须仍与调用者读取时一致。

命令不接收任意 shell 字符串或调用方增加的参数，仅使用本机固定 argv；后台不会启动 Codex/Claude 模型。需要新能力时，由拥有者在统一配置中明确增加命令。

### 大文件传输

读取块为 `read_chunk`；上传分为 `upload_begin`、`upload_chunk`、`upload_finish`。每块至多 512 KiB，目标端检查偏移、块 SHA256、最终大小与完整 SHA256，全部通过后才替换目标文件。中间内容保存在设备运行目录，不作为已交付文件。

调用方可以用 CLI 自动完成分块，无需逐块提示模型：

```sh
python3 agent_board.py network --config .runtime/client.json resource-copy \
  --source resource-源编号 --source-path dist/package.zip \
  --target resource-目标编号 --target-path public/agent-board/package.zip \
  --expected-sha256 absent --request-id release-package-v1
```

连接丢失后重用同一命令与 request-id。源内容变化或目标已有不同文件时停止，不覆盖原始归档。操作账本保留分块请求与结果；超大规模资源库同步应使用专门的对象存储，不能把本接口当作无限容量同步盘。

## 凭据只接入一次

`credential_refs` 是统一配置里的引用目录，不保存新的明文副本：

```json
{
  "credential_refs": {
    "myweb.notion.token": {
      "kind": "dotenv",
      "path": "/Users/om/projects/MyWeb/.env.local",
      "name": "NOTION_TOKEN"
    }
  }
}
```

支持进程环境变量 `env`、既有单值文件 `file`、既有环境文件中的某一项 `dotenv`、Mac 钥匙串 `keychain`。值在目标设备执行时读取，目录、通知与 MCP 结果只显示引用名。命令将引用显式映射到环境变量；服务将其映射到固定请求头或配置绑定。不会把浏览器会话、模型登录或所有凭据复制到其他电脑。

`services` 中的接口固定方法、URL、参数格式与鉴权头。参数不能任意更改主机或增加路径。`parameter_refs`、`body_bindings` 引用本机配置；`body_fixed` 强制固定字段；`guard` 可在写入前核对远端对象属于指定项目。服务响应丢失时返回 `uncertain`，不自动重试可能已经成功的 POST/PATCH。

MyWeb 的登记示例提供博客结构查询、文章查询、创建未发布草稿、读取文章、更新属性、追加内容。新草稿强制 `Published=false`，文章读取/更新/追加前检查所属博客数据库。实际发布仍必须来自当前用户的授权。数据库与 token 直接引用 MyWeb 现有 `.env.local`。

## 恢复与验收

- 队列在 Hub SQLite 中持久保存，操作只由所属设备原子认领。
- 执行前先写本机开始记录；完成后持久保存回执，再向 Hub 回报。
- 重启后优先补交已保存的回执；只有开始记录时标为不确定，绝不自动重做。
- 过期队列、权限撤回、资源配置改变会停止旧请求，避免延后执行已经失效的意图。
- `upgrade` 备份原配置和 SQLite，在一致性快照中校验全部表记录数；迁移只增加表。

自动测试：`python3 -m unittest discover -q`。包含真实本地 HTTP、两套设备身份和独立 MCP 进程，不等于 Windows 原生实机通过。最终跨机验收需要实际 Windows 在线并加载新客户端，以其身份发现 MyWeb、读取上下文、执行指定操作并返回结果。

本基础设施不会自动执行历史未读消息中的发布任务，不会替另一会话 ack，也不会将既有待验收任务自动标为完成。

## 升级包统一存放 SMB

日常通过 Git 获取程序。升级包归档到 SMB 共享，供各设备从同一位置获取；不要把聊天附件或某台设备的 dist 目录当成共享发布位置。

发布位置保存在现有统一配置的 `distribution.smb_shares`。每项包含 `name`、本机可访问的 `path` 和对应 `uri`；依赖挂载盘时加上 `mount`，发布前检查挂载点仍然在线。路由器共享需要先使用现有凭据挂载，再将其加入同一列表；配置中不保存 SMB 明文密码。

当前 Mac 发布根目录是 `/Volumes/superdisk/data/AgentBoard/releases`，Windows 对应 `\\192.168.1.199\data\AgentBoard\releases`。继续使用各设备既有的 SMB 登录。

```sh
# 先完成测试、提交并推送当前 main，再发布同一提交的归档。
python3 scripts/package_network.py --publish --config .runtime/config.json
```

发布器要求源码已提交，目录采用 `版本-提交号`，复制后回读 SHA256，通过后才更新 `latest.json`。同一提交的包若内容不同会拒绝覆盖；旧版本目录保留。未挂载的共享会报错，不会自动在空挂载点创建一个假共享目录。该命令不修改 Git 远端，也不替其他设备拉取或启动 Agent。

Windows 可读取 `latest.json` 中的 `directory`、`file`、`source_commit` 和 `sha256`，用 `Get-FileHash -Algorithm SHA256` 核对同目录的包。真实 Windows 下载和校验仍应由 Windows 自己记录结果。
