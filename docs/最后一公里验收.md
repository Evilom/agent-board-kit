# 从双向连接到实际工作续接

更新日期：2026-09-20。目标：用户在 Windows 说“把当前工程的这次更新整理到 MyWeb”，助手读取已登记资料，在 Mac 创建可核对的博客草稿，将结果带回 Windows。工程位置、资料入口、博客目标和凭据引用只登记一次。

当前已通过双向设备操作。尚未通过上述完整业务流程，不能用设备在线或 `ecosystem-check` 通过替代。

## 1. 当前聊天能够使用设备工具

Windows 12:05 CST 的实测报告表明，设备连接正常，但当时聊天没有绑定设备级 MCP。已有登录和 Board 配对继续使用原文件。

在 **Windows 本机 Codex 宿主**确认下列连接；先查看是否已存在相同配置，不重复增加不同名称的入口：

```powershell
codex mcp list
codex mcp add agent_ecosystem -- C:\Python312\python.exe E:\projects\agent-board-kit\agent_board.py network --config E:\projects\agent-board-kit\.runtime\client.json ecosystem-mcp
```

其他支持本机 STDIO MCP 的聊天宿主，使用 `network --config .runtime/client.json ecosystem-connection` 输出的命令配置。本地 Codex 配置不等于网页聊天的工具绑定；必须确认实际使用的宿主。Codex 的保存、重载和当前服务器查看方式见 [OpenAI 官方 MCP 文档](https://developers.openai.com/zh-Hans/docs/extend/mcp)。

验收：在实际 Windows 聊天里调用 `board_resources` 找到 MyWeb，`board_remote` 读取 context，`board_operation` 返回真实内容。仅列出配置或以 CLI 成功代查，不能记为聊天工具已接入。

## 2. 登记当前 Windows 工程

用户已选择换一个当前工程，不执行旧 Qijiepai 发布消息。等待工程名称或路径、这次博客内容目标，再检查已有工程规则和资料；不要求用户重新粘贴密钥。

由工程所属的 Windows 设备在原 `.runtime/client.json` 的 `resources` 中登记工程别名、实际根目录、明确的 `read_prefixes`、`context_files`、`knowledge_prefixes` 和允许的设备。使用已有 `resource-add`，先验证备份，保留其他资源和原配对。

在该工程已有文档中保存一份工作流说明并列入 `context_files`：

| 关系 | 保存内容 |
| --- | --- |
| 源工程 | Windows 资源 key、工程别名、版本核对方式 |
| 资料 | 已授权的发布说明、截图与文章资料路径 |
| 目标 | Mac 的 MyWeb 资源；已存在的文章 ID 或新草稿规则 |
| 知识 | 现有知识来源与查询关键词，不复制或重建知识库 |
| 凭据 | 目标设备已有引用名称，不复制密钥值 |
| 验证 | 草稿读取、对应图片检查、适用的网站构建/预览 |

Windows 本地助手可直接读取当前授权工程；Mac 需要访问这些资料时使用 Windows 资源的 context/read/search。双向目录授权与已有知识复用分别配置，不能把共享知识误当作整个磁盘授权。

## 3. 用一篇真实草稿完成链路

1. Windows 当前助手读取源工程的规则、版本、资料和上述工作流说明。
2. 查询 MyWeb 资源与 context，调用现有 `blog-schema`、`blog-query` 确认文章结构与目标，沿用 Mac 的 `myweb.notion.token`、`myweb.notion.blog-database` 引用。
3. 依据本次内容目标生成草稿；使用固定 `request_id` 调用 `blog-create-draft`，由 Mac 强制 `Published=false`。出现 `uncertain` 时先核实原结果，不能重复新建。
4. 通过 `blog-read` 核对属性，`blog-content` 回读正文，按 `has_more` 使用 `blog-content-next` 读完顶层分页。核对标题、正文、来源及图片；若存在嵌套块须继续解决子块读取，不能宣称全文通过。运行适用检查并给出可查看的草稿或预览。草稿在 Notion 中存在不代表公开网站已展示。
5. Windows 以自己的身份取回终态结果；记录 operation ID、草稿 ID/链接、内容依据、校验结果和 `retrieval`。Mac 不代填 Windows 确认。
6. 在重载工具或设备服务后，再次通过工程别名找到同一关系，并读取同一草稿；不重新询问已登记路径或密钥。正式发布按当前文章的明确授权执行。

只有这条流程通过，才能宣布这一对工程可以实际续接。其他设备和工程逐项登记与验证，不从一次通过推断全部已接通。
