# 0.4.1 连接恢复与跨设备结果验收

验证日期：2026-09-20。关联 Mac 基础设施任务 `work-5d168143cfe6400eb99300db2db5ae91`。

## 当前结论

本节保留 0.4.1 的设备互通验收；后续分页修复、Mac 0.4.2 服务与完整回归结果见 [0.4.2 验收记录](升级验收记录-0.4.2.md)。

截至 2026-09-20 06:40 UTC，Mac 与 Windows 均运行 0.4.1，设备在线且无连接冲突。Windows → Mac 的 MyWeb 上下文与图片检查、Mac → Windows 的授权版本文件读取，都有各自请求端的真实取回确认。设备工具通道已双向验证；实际博客更新、Windows 聊天工具绑定和小米 SMB 传输仍需单独验收。

Windows 原生测试报告为 74 通过、1 错误、1 跳过。错误发生在进程测试的临时目录清理：资源锁释放后，设备进程尚未完全退出，仍持有 `device.log`。本次修正测试，让 Windows 持有确切子进程的同步句柄并等待实际退出，再清理目录；不跳过测试、不增加固定延迟、不改变设备服务逻辑。修正后 Mac 完整 76 项测试为 75 通过、1 跳过；Windows 原生复测待完成。

## 修复

- 服务增加操作系统单实例锁与可读的进程所有者记录。
- 竞争资源执行器等待接管，等待期间不再发布心跳或覆盖资源目录。此前它会退出工作线程，但设备进程继续发心跳。
- 服务进程消失后，设备子进程通过父进程管道关闭停止，取消本地执行并释放锁；不依赖 Windows 的 SIGTERM 行为。
- Hub 记录近期连接，识别同一设备重叠的不同版本或运行实例；网页显示需要处理的连接冲突。
- 请求端对收到的结果提交 SHA256 确认。只允许原请求身份确认，Mac 不能代 Windows 确认。
- 新增 `ecosystem-check`，复用原配对、目录和凭据引用，输出发现、上下文、指定命令和结果取回的实际证据。
