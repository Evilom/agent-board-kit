# Agent Board 0.2：跨设备 Agent 协作

主电脑安装服务端和客户端，副电脑安装客户端。所有设备使用同一份任务、消息和授权知识，实际 Agent 和设备执行仍在各自电脑上运行。中文界面包含任务、设备、Agent、消息和知识库。

程序只依赖 Python 3.9+ 的标准库。Dagu 是独立、按需安装的执行后端；不复制其源码，不把它的运行结果直接当作任务验收通过。任务可以是资料整理、排查、分析或其他明确授权的工作，不要求 Git 仓库。

## 1. 主电脑启动

在项目目录中首次配置：

```sh
python3 agent_board.py network --config .runtime/config.json init-server \
  --project my-work --device mac-main --root /你的/工作目录
python3 agent_board.py network --config .runtime/config.json service
```

另开终端打开中文界面：

```sh
python3 agent_board.py network --config .runtime/config.json open
```

默认只监听本机 `127.0.0.1:8940`。`open` 使用 60 秒有效的一次性登录链接，浏览器仅保存短期 HttpOnly 会话 Cookie，不保存设备令牌。主电脑的 service 同时运行服务端和设备心跳；副电脑 service 只运行本机客户端。没有 Dagu 时，任务、Agent 接入、消息和知识查询仍可使用。

已有 0.1 配置先升级，再重启服务：

```sh
python3 agent_board.py network --config .runtime/config.json upgrade
```

升级会备份配置与 SQLite，检查备份完整性，增加协作表；保留旧任务和审计记录。已有执行权限的成员新增 `collaborate` 权限，只读成员保持只读。原本地 CLI 与 `/v1/tasks` 接口继续保留。

## 2. Windows 首次接入

Windows 安装 Python 3.9+、Git，以及需要使用的 Codex / Claude Code，分别完成本机登录。拉取主分支：

```powershell
git clone https://github.com/Evilom/agent-board-kit.git
cd agent-board-kit
git switch main
```

在主电脑配置可从副电脑访问的服务地址。推荐 HTTPS；可信局域网可明确选择 HTTP：在主电脑统一配置中设置 `listen.host` 为对应局域网 IP，`listen.allow_private_http` 为 `true`，并让 `hub.url` 指向同一 IP、设置 `hub.allow_private_http: true`。只开放 Board 端口；Dagu API 继续绑定回环地址。

然后在主电脑执行配对（以下 IP 和工作路径要换成实际值）：

```sh
python3 agent_board.py network --config .runtime/config.json pair \
  --project my-work --device windows-main --environment windows-native \
  --workspace windows-work --os Windows --root 'D:\Work\MyProject' \
  --hub-url http://192.168.1.100:8940 --allow-private-http \
  --coordinator 192.168.1.100:51855
```

主电脑生成 `.runtime/pairings/windows-main/client.json` 和独立 `.token` 文件。通过可信方式把这两个文件放到 Windows 的 `.runtime/` 下，保持令牌文件名不变。不要提交配对文件到 Git。重启主电脑服务加载新增权限。

Windows 运行：

```powershell
.\scripts\client.ps1 -Config .runtime\client.json
```

另开终端：

```powershell
.\scripts\open.ps1 -Config .runtime\client.json
```

配对的客户端默认关闭 Dagu 执行；任务、消息、知识和 Agent 接入可直接使用。Windows 原生实机联调仍需连接实际设备；本轮在 Mac 用独立客户端进程验证了协议，不把这项当作 Windows 实机通过。

## 3. 接入 Codex / Claude Code

每台设备沿用本机工具、登录与权限。终端中运行：

```sh
python3 agent_board.py network --config .runtime/config.json agent \
  --project my-work --workspace mac-main --name codex-mac --provider codex
python3 agent_board.py network --config .runtime/config.json agent \
  --project my-work --workspace mac-main --name claude-mac --provider claude
```

Windows 将 `python3` 换成 `python`，配置换成 `.runtime/client.json`，工作区换成 `windows-work`。每个同时运行的会话使用不同 `--name`。

启动命令仅向当前 CLI 会话传递 MCP 配置，不改全局 Agent 设置，不复制 API 密钥。如果 PATH 中的旧 CLI 无法使用当前模型，可在本设备统一配置的 `agent_commands` 中指定已安装的新版本可执行文件，例如 `{"codex":"/绝对路径/codex","claude":"/绝对路径/claude"}`。现有支持 MCP 的应用可把 `agent` 换成 `connection` 获取接入配置。该应用加载 MCP 后，会话才会出现在界面中；不会自动接管已打开但尚未接入的聊天窗口。

主要工具：

| 工具 | 用途 |
| --- | --- |
| `board_status` / `board_tasks` / `board_task` | 查看身份、设备、Agent 和完整任务 |
| `board_claim` / `board_progress` / `board_block` | 认领、汇报、报告阻塞 |
| `board_message` / `board_inbox` / `board_ack` | 发消息、读取收件箱、确认已处理 |
| `board_handoff` / `board_receive` | 停止当前修改后交接，由接收方确认 |
| `board_knowledge` | 查询允许访问的原文来源与版本 |
| `board_artifact` / `board_result` | 上传真实产物并按验收项提交依据 |

收件箱由 Agent 在工作阶段主动轮询。消息送达与处理确认分别记录，不会把未读消息说成对方已经执行。任务消息对该项目成员可见；未关联任务的消息只对发送方和接收设备可见。

断线后 75 秒显示离线。断线不会授予新执行权。恢复仍持有任务的会话时，在原命令追加 `--session 原会话编号`；从 Agent 列表或错误提示可取得编号。会话编号绑定设备凭据，其他设备无法冒用。

## 4. 一个完整工作流程

1. 在任务页填写目标、相对路径范围、约束、逐条验收标准；可以指定 Agent。
2. Agent 读取完整任务后原子认领，获得本次执行编号。两个 Agent 同时认领时只有一个成功。
3. 执行方报告进度、遇到阻塞时说明需要什么帮助。可在任务消息中联系另一设备上的 Agent。
4. 交接前停止当前修改，提供已完成、剩余工作、来源和注意事项。接收方确认后保持同一任务编号，生成新的执行编号。
5. 旧执行不能覆盖新执行。Agent 上传产物时校验 SHA256，并绑定任务和执行编号。
6. 结果必须逐条列出通过、失败或未验证状态及依据。只有全部通过且有人工验收意见，任务才进入已完成。

范围和交接声明是协作约束，不是任意编辑器的操作系统文件锁。原有项目文件不会自动复制、清空或回写；资料/源码的跨机传输需要单独明确输入和目标。Git 在本指南中负责程序分发与更新。

## 5. 设备执行：复用 Dagu

需要调用设备能力时在对应机器安装固定版本 Dagu：

```sh
python3 agent_board.py network --config .runtime/config.json runtime-install
```

安装程序验证官方发布包 SHA256。服务端与 worker 通过独立进程连接。主电脑本机回环执行开箱可用；远程执行须在主电脑 coordinator 和 Windows worker 中配置互信的 mTLS 证书，配置格式见 [原生执行配置](CROSS_DEVICE.zh-CN.md)。Windows 配置增加 `execution_enabled: true` 后重启客户端。协作本身不需要配置执行证书。

任务详情中点击“调用设备能力”选择目标工作区：

- **环境检查**：系统、Python 和 Agent 版本。
- **目录检查**：授权相对路径内的文件清单和 SHA256；跳过运行数据、常见依赖目录和凭据文件，最多 200 文件。
- **Codex 只读分析**：调用已有 Codex CLI，启用 `read-only` 沙箱。
- **Claude Code 只读分析**：只开放 `Read,Glob,Grep` 内置工具，禁用外部 MCP；不等同于操作系统级读路径隔离。

后两项需要目标设备的统一配置明确加入：

```json
"agent_capabilities": ["agent.codex.read/v1", "agent.claude.read/v1"]
```

Agent 的任务范围会写入指令，底层读取权限仍受本机 Agent 配置约束。远程设备必须在本机授权这些能力；服务端不能仅通过派发任务绕过这一开关。

执行回执绑定设备、环境、任务和执行编号。成功退出只会进入待验收；用户对照真实输出“逐项审核”后再验收。网络错误显示待核实，使用原执行编号查询，绝不因响应丢失再次启动。任务尚未发出时可“重试连接设备”；已经结束的执行可退回补充，再明确启动新的一次执行。

## 6. 复用已有知识

保留现有原文和索引。统一配置中的 `knowledge_sources` 为项目指定资料根目录与允许的相对前缀：

```json
"project-docs": {
  "kind": "documents", "root": "/允许的项目目录",
  "projects": ["my-work"], "prefixes": ["README.md", "docs"]
}
```

已有自定义 QMD 网关支持 `qmd-http` 适配，契约为 `POST /search {query,n}` 和 `{ok,results:[{file:"qmd://collection/path",docid}]}`；这不表示任意 QMD 原生 HTTP 接口具有相同契约。

查询会再次读取授权原文，排除越界路径、删除文件和过期索引片段，返回 SHA256 与来源。界面可复制来源和摘要到任务消息/验收依据中。系统不重建、不删除原知识库，也不把文档陈述当作代码实现证据。

## 7. 拉取更新与数据位置

先停止本设备的 service，然后执行：

```powershell
.\scripts\update.ps1 -Config .runtime\client.json
```

Mac：

```sh
./scripts/update.sh .runtime/config.json
```

更新脚本要求当前分支为 `main` 且源码无未保存改动，执行 `git pull --ff-only origin main`，随后备份升级配置、运行网络与协作测试。不会 `reset --hard`，不会覆盖用户修改。之后重启 service，再 open。

`.runtime/` 保存本机配置、设备令牌、运行日志、数据库和备份，始终被 Git 忽略；配对文件通过安全通道传递。`scripts/package_network.py` 从明确的源码清单生成 ZIP，不打包运行数据和凭据。

## 架构与后续接入

Board 是协作任务的权威记录；Dagu 是具体执行后端；已有知识服务保留原始资料；Codex / Claude Code 管理自己的工具与交互会话。MCP 将这些会话接入 Board 的协作协议。本次未安装 HAPI / OpenClaw，也未另造远程终端、会话录屏、完整源码同步或自动审批系统；需要这些交互能力时，可再接现有 HAPI。
